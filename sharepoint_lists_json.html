Profesjonalne Rejestry Bankowe w Microsoft Lists z Formatowaniem JSON

Zastąp niekontrolowane arkusze kalkulacyjne audytowalnymi bazami Microsoft Lists. Formatowanie deklaratywne JSON umożliwia tworzenie czytelnych dla biznesu wskaźników graficznych (Pill badges, macierze ryzyka DORA, dynamiczne wskaźniki SLA) z zachowaniem pełnej integralności danych i zgodności z KNF Rekomendacja D.

📊

1. Dlaczego MS Lists zamiast Excela w Bankowości?

Analiza ryzyk operacyjnych i wymogów nadzorczych KNF / DORA

KNF Rek. D (G9) • DORA Art. 11

Praktyka prowadzenia rejestrów ryzyk, incydentów bezpieczeństwa, upoważnień i umów w plikach .xlsx jest jednym z najczęściej identyfikowanych uchybień podczas audytów KNF i audytów wewnętrznych. Poniższe zestawienie wyjaśnia różnice kluczowe dla Departamentów Compliance i CISO:

❌ Ryzyka Arkuszy Excel w Banku

  • Brak ścieżki audytowej: Użytkownik może niepostrzeżenie nadpisać lub skasować komórkę bez zapisu kto, kiedy i co zmienił.
  • Ryzyko usunięcia formuł: Przypadkowe skasowanie formuły kalkulującej scoring ryzyka niszczy spójność całego rejestru.
  • Brak walidacji danych: Dowolność wpisywania wartości (np. literówki w nazwie klienta uniemożliwiające agregację).
  • Kolizje współbieżności: Blokady pliku lub konflikty synchronizacji przy jednoczesnej pracy kilkunastu oficerów.

✅ Bezpieczeństwo Microsoft Lists

  • Niezaprzeczalny Audit Trail: Każda modyfikacja rejestrowana w historii wersji (kto, data, poprzednia i nowa wartość) oraz w Unified Audit Log.
  • Oddzielenie danych od prezentacji: Logika formatowania JSON znajduje się w warstwie widoku – użytkownik nie może uszkodzić formuł ani logiki.
  • Wymuszone typowanie: Ścisłe listy wyboru (Choice), pola odnośników (Lookup) i walidacje uniemożliwiają wprowadzenie błędnych danych.
  • Automatyzacja powiadomień: Wbudowane reguły i przepływy Power Automate natychmiast informujące Właściciela Ryzyka o incydencie.
⚖️
Wymóg DORA (UE 2022/2554) – Art. 11: Podmioty finansowe są zobowiązane do utrzymywania scentralizowanego, ustrukturyzowanego rejestru informacji o wszystkich ustaleniach umownych dotyczących korzystania z usług ICT świadczonych przez dostawców zewnętrznych. Microsoft Lists z formatowaniem JSON idealnie spełnia te kryteria bez potrzeby zakupu dedykowanych systemów zewnętrznych.

3. Pill Badges: Nowoczesne Etykiety Statusów w JSON

Formatowanie kolumny wyboru (Choice) z automatyczną zmianą barw i zaokrągleniami

Formatowanie Kolumny JSON

Formatowanie zastępuje szary, zwykły tekst elegancką „pigułką” (Pill Badge), której kolor, ramka i ikona zmieniają się dynamicznie w oparciu o wartość pola @currentField.

Szablon: Status Pill Badge (Nowy / W analizie / Zaakceptowany / Zablokowany)
Cel: Kolumna [StatusIncydentu]
Podgląd Renderowania w Liście ● Live CSS Preview
Gdy wartość = "Nowy":
● Nowy
Gdy wartość = "W analizie":
⏳ W analizie
Gdy wartość = "Zaakceptowany":
✓ Zaakceptowany
Gdy wartość = "Zablokowany":
✕ Zablokowany 
{
  "$schema": "https://developer.microsoft.com/json-schemas/sp/v2/column-formatting.schema.json",
  "elmType": "div",
  "style": {
    "display": "inline-flex",
    "align-items": "center",
    "padding": "4px 10px",
    "border-radius": "14px",
    "font-size": "12px",
    "font-weight": "700",
    "letter-spacing": "0.02em",
    "background-color": "=if(@currentField == 'Nowy', '#eff6ff', if(@currentField == 'W analizie', '#fffbeb', if(@currentField == 'Zaakceptowany', '#ecfdf5', '#fff1f2')))",
    "color": "=if(@currentField == 'Nowy', '#1d4ed8', if(@currentField == 'W analizie', '#b45309', if(@currentField == 'Zaakceptowany', '#047857', '#be123c')))",
    "border": "=if(@currentField == 'Nowy', '1px solid #bfdbfe', if(@currentField == 'W analizie', '1px solid #fde68a', if(@currentField == 'Zaakceptowany', '1px solid #a7f3d0', '1px solid #fecdd3')))"
  },
  "children": [
    {
      "elmType": "span",
      "style": { "margin-right": "5px" },
      "txtContent": "=if(@currentField == 'Nowy', '●', if(@currentField == 'W analizie', '⏳', if(@currentField == 'Zaakceptowany', '✓', '✕')))"
    },
    {
      "elmType": "span",
      "txtContent": "@currentField"
    }
  ]
}

4. Dynamiczna Macierz Ryzyka (Risk Heatmap w JSON)

Warunkowe kolorowanie poziomu ryzyka z automatyczną kalkulacją i pulsowaniem krytycznym

DORA Risk Matrix

W rejestrze DORA poziom ryzyka (iloczyn Prawdopodobieństwo x Wpływ) przyjmuje wartości od 1 do 25. Poniższy format dynamicznie przypisuje klasę barwną i etykietę słowną do wartości liczbowej:

Szablon: Heatmapa Poziomu Ryzyka (Low / Med / High / Critical)
Cel: Kolumna [PoziomRyzyka]
Podgląd Poziomów Ryzyka ● Live CSS Preview
Wartość 1–4 (Niski):
NISKIE (Score: 2)
Wartość 5–9 (Średni):
ŚREDNIE (Score: 6)
Wartość 10–15 (Wysoki):
WYSOKIE (Score: 12)
Wartość 16–25 (Krytyczny – DORA):
⚠️ KRYTYCZNE (Score: 20)

5. Paski Postępu & Dynamiczny Wskaźnik Upływu SLA

Porównanie z datą bieżącą @now i alarmowanie o zbliżającym się terminie incydentu

Kalkulacja Daty @now

W bankowości każdy incydent cyberbezpieczeństwa posiada określone w procedurze SLA (np. 4h, 24h, 72h). SharePoint pozwala za pomocą @now obliczyć liczbę milisekund do upływu terminu i natychmiast zaalarmować zespół operacyjny:

Szablon: SLA Countdown Badge (Przed terminem / <24h / Przekroczone)
Cel: Kolumna daty [TerminSLA]
Podgląd Stanu SLA w Zależności od Terminu ● Live CSS Preview
SLA: Zgodne z harmonogramem (>24h) Bezpieczne
SLA: Mniej niż 24h do końca! Uwaga
SLA: PRZEKROCZONE! (Audyt Alert) PRZETERMINOWANE 
{
  "$schema": "https://developer.microsoft.com/json-schemas/sp/v2/column-formatting.schema.json",
  "elmType": "div",
  "style": {
    "display": "inline-flex",
    "align-items": "center",
    "gap": "6px",
    "padding": "4px 10px",
    "border-radius": "6px",
    "font-size": "12px",
    "font-weight": "700",
    "background-color": "=if(@currentField < @now, '#fee2e2', if(@currentField < @now + 86400000, '#fef3c7', '#ecfdf5'))",
    "color": "=if(@currentField < @now, '#991b1b', if(@currentField < @now + 86400000, '#92400e', '#065f46'))",
    "border": "=if(@currentField < @now, '1px solid #fca5a5', if(@currentField < @now + 86400000, '1px solid #fde68a', '1px solid #a7f3d0'))"
  },
  "children": [
    {
      "elmType": "span",
      "txtContent": "=if(@currentField < @now, '🚨 PO TERMINIE: ', if(@currentField < @now + 86400000, '⚠️ PILNE (<24h): ', '⏱️ W TERMINIE: ')) + toLocaleDateString(@currentField)"
    }
  ]
}

8. Dobre Praktyki, Najczęstsze Błędy & FAQ

Praktyczne wskazówki dla administratorów i twórców formularzy

Troubleshooting
Dlaczego mój kod JSON nie działa i wyświetla błąd składni (JSON Parsing Error)? ▼
Najczęstszym błędem jest używanie niedozwolonych cudzysłowów drukarskich (tzw. curly quotes „”) zamiast czystych cudzysłowów programistycznych "" lub brak przecinka między właściwościami obiektu. Drugim powodem jest użycie nazwy wyświetlanej (Display Name) zamiast wewnętrznej nazwy technicznej kolumny (Internal Name, np. [$Status_x0020_Incydentu] zamiast [$Status Incydentu]).
Czy formatowanie JSON modyfikuje wartości przechowywane w bazie danych? ▼
Nie. Formatowanie JSON działa wyłącznie w warstwie prezentacji (interfejsu użytkownika w przeglądarce). Wartości w bazie danych, historii wersji oraz przy eksporcie do Power BI / Excela pozostają surowymi, niemodyfikowanymi danymi. Jest to kluczowe z punktu widzenia audytu KNF, ponieważ nie zachodzi ryzyko przekłamania surowych wpisów.
Jak odwołać się do innych kolumn w formacie kolumny bieżącej? ▼
Do wartości bieżącej kolumny odwołujesz się słowem kluczowym @currentField. Aby odwołać się do innej kolumny w tym samym wierszu (np. pobrać datę SLA podczas kolorowania statusu), użyj składni [$NazwaWewnetrznaKolumny]. Pamiętaj, że odwoływana kolumna musi być dodana do bieżącego widoku listy, w przeciwnym razie SharePoint zwróci pustą wartość.
Czy formatowanie kolumn JSON działa w aplikacji mobilnej Microsoft Lists / Teams? ▼
Tak! Od wersji schematu v2 (column-formatting.schema.json) formatowanie JSON jest w pełni respektowane w aplikacji mobilnej Microsoft Lists na iOS/Android oraz w kartach list osadzonych w kanałach Microsoft Teams.
