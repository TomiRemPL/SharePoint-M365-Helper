Encyklopedia Silnika Formatowania JSON w SharePoint Online & M365

Formatowanie deklaratywne JSON pozwala na transformację surowych danych tabelarycznych w nowoczesne, interaktywne interfejsy bez konieczności kompilowania i wdrażania paczek SPFx. Silnik renderujący SharePoint przetwarza obiekty JSON w izolowanym, bezpiecznym środowisku przeglądarki, gwarantując pełną zgodność z rygorystycznymi wymogami bezpieczeństwa sektora bankowego (DORA Art. 9/11 oraz Wytyczne KNF w zakresie zarządzania obszarami technologii ICT).

⚙️

1. Architektura Silnika & Schematy JSON ($schema)

Zasada działania silnika deklaratywnego i oficjalne schematy walidacji Microsoftu

Microsoft Learn Standard

W odróżnieniu od rozszerzeń SharePoint Framework (SPFx Application Customizers / Field Customizers), które wymagają uprawnień administratora dzierżawy (Tenant Admin) i deploymentu plików JavaScript do katalogu App Catalog, formatowanie JSON jest deklaratywnym szablonem DOM. Zapisywany jest bezpośrednio we właściwościach kolumny, widoku lub formularza listy. Silnik SharePoint parsuje JSON w locie i buduje bezpieczne drzewo elementów HTML, automatycznie odrzucając skrypty oraz niebezpieczne atrybuty (ochrona przed atakami XSS).

Zastosowanie Wersja Schematu Oficjalny URI Schematu ($schema) Główny Zakres Zastosowania
Formatowanie Kolumny v2 https://developer.microsoft.com/json-schemas/sp/v2/column-formatting.schema.json Pojedyncza komórka tabeli listy lub biblioteki dokumentów (Pill, Badge, Avatar, SLA).
Formatowanie Wiersza / Widoku v2 https://developer.microsoft.com/json-schemas/sp/v2/row-formatting.schema.json Cały wiersz listy (wiersz alternatywny, widok kafelkowy/Kanban, hideSelection, hideColumnHeader).
Formatowanie Kafelków (Galeria) v1 https://developer.microsoft.com/json-schemas/sp/v1/tile-formatting.schema.json Widok kafelkowy (Compact Card / Gallery View) bibliotek procedur i umów.
Formatowanie Formularza Listy v1 https://developer.microsoft.com/json-schemas/sp/v1/form-formatting.schema.json Niestandardowy nagłówek (header), sekcje wielokolumnowe (body) oraz stopka (footer).
💡
Wskazówka VS Code i IntelliSense: Dodanie klucza "$schema" na samym początku pliku JSON w Visual Studio Code lub dowolnym edytorze kodu włącza pełne podpowiadanie składni (IntelliSense), automatyczną walidację dozwolonych właściwości oraz weryfikację typów argumentów w locie!

2. Anatomia Bloków Kodu Formatującego

Szczegółowy opis wszystkich węzłów drzewa JSON akceptowanych przez silnik SharePoint

Węzły DOM & Właściwości

Każdy element w schemacie formatowania reprezentuje węzeł wirtualnego DOM, który SharePoint przekształca w bezpieczny znacznik HTML. Poniższa tabela stanowi kompletną specyfikację każdego dostępnego bloku:

Klucz / Blok JSON Typ danych Dozwolone Wartości / Opcje Rola & Znaczenie Architektoniczne
$schema String (URL) Oficjalny adres URL schematu Microsoft Wskazuje schemat walidacyjny. Nie wpływa bezpośrednio na runtime, lecz jest kluczowy dla edytorów i walidatorów.
elmType String div, span, a, button, img, svg, path, p Definiuje renderowany element HTML. Inne tagi (np. input, iframe, script) są bezwzględnie blokowane.
txtContent String / Wyrażenie Tekst statyczny, np. "Status" lub wyrażenie np. "=@currentField" Wstrzykuje zawartość tekstową do wnętrza elementu. Chroni przed XSS przez automatyczne escapowanie encji HTML.
style Object (Map) Pary klucz:wartość (np. "display": "flex", "align-items": "center") Deklaracja styli CSS w linii. Obsługuje wartości statyczne oraz dynamiczne wyrażenia warunkowe =if(...).
attributes Object (Map) class, iconName, href, target, title, src, role, aria-* Nadaje standardowe atrybuty HTML oraz nazwę ikony z zestawu Fluent UI Fabric Icons (np. "iconName": "Shield").
children Array [Element] Tablica obiektów potomnych o tej samej strukturze Buduje hierarchię drzewa DOM (np. kontener div zawierający ikonę span oraz tekst span).
customRowAction Object / String defaultClick, editProps, quickForm, share, delete, executeFlow, openContextMenu Przypisuje natywną akcję kliknięcia platformy SharePoint do przycisku lub kontenera (np. uruchomienie Power Automate).
customCardProps Object formatter, openOnEvent, directionalHint, isBeakVisible Konfiguruje pływającą kartę podglądu (hover card / popover flyout), która pojawia się po najechaniu myszą lub kliknięciu.
forEach Object iterator: "nazwaZmiennej", in: "@currentField" Pętla iterująca po kolekcjach (np. kolumna wielokrotnego wyboru, wielu właścicieli, multi-lookup).
defaultHoverField Boolean true / false Włącza natywną kartę profilową kontaktu (Microsoft Graph Persona Card) dla kolumn typu Osoba lub Grupa.
📄 Kompleksowy Przykład: Wzorcowy Blok Elementu JSON z Pełną Hierarchią 
{
  "$schema": "https://developer.microsoft.com/json-schemas/sp/v2/column-formatting.schema.json",
  "elmType": "div",
  "style": {
    "display": "inline-flex",
    "align-items": "center",
    "justify-content": "space-between",
    "gap": "8px",
    "padding": "6px 12px",
    "border-radius": "16px",
    "background-color": "=if(@currentField == 'KRYTYCZNE', '#ffe4e6', '#ecfdf5')",
    "border": "=if(@currentField == 'KRYTYCZNE', '1px solid #fda4af', '1px solid #a7f3d0')",
    "color": "=if(@currentField == 'KRYTYCZNE', '#9f1239', '#065f46')",
    "font-size": "12px",
    "font-weight": "700"
  },
  "children": [
    {
      "elmType": "span",
      "attributes": {
        "iconName": "=if(@currentField == 'KRYTYCZNE', 'WarningSolid', 'CompletedSolid')"
      },
      "style": {
        "font-size": "14px"
      }
    },
    {
      "elmType": "span",
      "txtContent": "@currentField"
    }
  ]
}

3. Kompletny Leksykon Styli CSS (Safe CSS Engine)

Wszystkie dozwolone właściwości CSS, akceptowane wartości i reguły sanityzacji

Właściwości & Wartości

Silnik SharePoint używa wbudowanego arkusza stylów i parsera bezpieczeństwa. Nazwy właściwości mogą być zapisywane w notacji kebab-case (np. align-items) lub camelCase (np. alignItems). Poniższe zestawienie wyczerpuje dozwolony zestaw styli dla architektów i deweloperów M365:

Grupa Właściwość CSS Dopuszczalne Wartości Zastosowanie w SharePoint
Układ Flexbox display flex, inline-flex, block, inline-block, none, grid Główny model pozycjonowania badge'y, wskaźników i kafelków. Wartość none ukrywa element warunkowo.
flex-direction row, column, row-reverse, column-reverse Kierunek osi głównej (np. column dla pionowego układu tytułu i podtytułu).
align-items center, flex-start, flex-end, stretch, baseline Wyrównanie dzieci w osi poprzecznej (np. idealne wycentrowanie ikony względem etykiety).
justify-content center, flex-start, flex-end, space-between, space-around, space-evenly Rozłożenie elementów na osi głównej (np. space-between rozsuwa nazwę i wskaźnik statusu).
flex-wrap nowrap, wrap, wrap-reverse Zawijanie wielokrotnych tagów/pilli przy braku miejsca w szerokości komórki.
gap Wartości jednostkowe: 4px, 8px, 12px, 0.5rem itp. Nowoczesny odstęp pomiędzy elementami potomnymi bez potrzeby używania marż zewnętrznych.
flex-grow Liczba całkowita (np. 0, 1, 2) Pozwala elementowi (np. tytułowi lub paskowi postępu) rozciągnąć się na dostępną przestrzeń.
flex-shrink Liczba całkowita (np. 0, 1) Wartość 0 zabezpiecza kluczowe ikony i przyciski przed ściśnięciem w wąskich kolumnach.
Wymiary & Box Model width / height Wartości w px, %, rem, fit-content, auto Precyzyjne wymiarowanie pasków SLA, awatarów i kontenerów.
min-width / max-width Wartości w px, %, rem Ochrona przed rozciąganiem tabeli przez długie numery spraw i kont bankowych.
padding Wartości w px (również cząstkowe: padding-left, padding-top itp.) Wewnętrzny margines otaczający zawartość etykiety lub przycisku.
margin Wartości w px, auto (oraz margin-top/bottom/left/right) Zewnętrzny odstęp od sąsiednich komórek. margin: auto służy do centrowania.
box-sizing border-box, content-box Zalecane border-box – padding i ramka są wliczane do całkowitej szerokości elementu.
overflow hidden, visible, auto, scroll Obcinanie nadmiarowej zawartości (kluczowe przy zaokrąglonych paskach postępu).
text-overflow ellipsis, clip Wyświetla wielokropek (...) przy obcięciu zbyt długiego tekstu.
Typografia font-size 11px, 12px, 14px, 0.85rem, 1rem itp. Ustalanie wielkości czcionki w zależności od hierarchii ważności informacji.
font-weight normal, bold, 400, 500, 600, 700, 800 Pogrubienie kluczowych parametrów finansowych, kwot i statusów.
color Kody HEX (np. #0f172a), rgba(), nazwy kolorów Kolorowanie tekstu, liczb ujemnych/dodatnich i alarmów audytowych.
text-align left, center, right, justify Wyrównywanie danych: kwoty i liczby do prawej, statusy do środka, opisy do lewej.
text-transform uppercase, lowercase, capitalize, none Wymuszenie wielkich liter dla identyfikatorów DORA, kodów SWIFT i skrótów GRC.
white-space nowrap, normal, pre-wrap Wartość nowrap gwarantuje, że pill statusowy nie zostanie złamany na dwa wiersze.
Tła & Ramki background-color Kody HEX, rgba(), transparent Tło kontenerów, pilli i alertów.
border Skrót CSS, np. 1px solid #e2e8f0 (oraz border-left itp.) Wyraźne obramowanie statusów i ramek akcentujących z lewej strony.
border-radius Wartości w px, % (np. 4px, 14px, 50%) Zaokrąglenia rogów: 50% dla idealnie okrągłych awatarów, 14px dla pilli.
box-shadow Cienie CSS, np. 0 2px 6px rgba(0,0,0,0.08) Subtelny efekt wyniesienia dla kafelków w widokach zarządczych.
Efekty & Kursor cursor pointer, default, not-allowed Wskazuje użytkownikowi, że element można kliknąć (np. przycisk uruchomienia Flow).
opacity Wartości od 0.0 do 1.0 (np. 0.5) Wyszaryzowanie pozycji archiwalnych lub zrealizowanych zadań.
transform rotate(deg), scale(), translate() Obracanie strzałek chevron i delikatne skalowanie elementów przy interakcji.
transition Standardowe przejścia, np. all 0.2s ease Płynne animacje najechania kursorem myszy na przyciski wiersza.
⚠️
Ograniczenia i Sanityzacja Microsoftu (Czego NIE wolno robić):
  • Właściwości position: fixed oraz position: absolute (próba wyjścia poza komórkę wiersza jest blokowana lub degraduje układ tabeli).
  • Wstrzykiwanie znaczników <script>, <iframe>, <style> lub atrybutów onclick / onload (blokowane pod kątem XSS).
  • Protokoły javascript: w atrybutach href (dozwolone wyłącznie https://, mailto:, tel:).
  • Niekontrolowane wartości z-index powodujące przesłanianie systemowego paska poleceń SharePoint.

4. Wyrażenia, Tokeny Kontekstowe & Funkcje

Logika warunkowa, manipulacje datami, ciągami znaków i obliczenia w JSON

Expression Engine

Silnik SharePoint obsługuje wyrażenia w notacji zbliżonej do formuł programu Microsoft Excel (zaczynające się od znaku równości =). Wyrażenia mogą dynamicznie sterować stylami CSS, treścią tekstową oraz atrybutami elementów:

🪙 Wbudowane Tokeny Kontekstowe

Specjalne zmienne wstrzykiwane przez środowisko uruchomieniowe SharePoint w momencie renderowania komórki:

  • @currentField – wartość bieżącej kolumny.
  • @currentField.title – imię i nazwisko osoby (dla kolumny Person).
  • @currentField.email – adres e-mail pracownika.
  • @currentField.lookupValue – tekst powiązany z listy nadrzędnej (Lookup).
  • [$NazwaWewnetrzna] – odwołanie do innej kolumny w tym samym wierszu.
  • @now – bieżący znacznik czasu (Unix timestamp w milisekundach).
  • @me – adres e-mail aktualnie zalogowanego użytkownika.
  • @rowIndex – bieżący indeks wiersza w widoku (liczony od 0).
  • @window.innerWidth – szerokość okna przeglądarki w pikselach.

🧮 Operatory Matematyczne i Logiczne

Dozwolone operatory w formułach =:

  • Warunkowe: if(warunek, prawda, fałsz) (zagnieżdżane).
  • Porównania: ==, !=, <, <=, >, >=.
  • Logiczne: && (AND), || (OR), ! (NOT).
  • Arytmetyczne: +, -, *, /, % (modulo).
  • Konwersje typów: Number('123'), toString(123), Boolean(...).
Kategoria Funkcja wbudowana Składnia i Przykład Opis działania
Manipulacja Tekstem indexOf() =indexOf(@currentField, '@bank.pl') Zwraca pozycję szukanego podciągu (lub -1 jeśli brak).
substring() =substring([$NumerIBAN], 0, 4) Wyciąga fragment tekstu od indeksu początkowego do końcowego.
toLowerCase() / toUpperCase() =toUpperCase(@currentField) Konwertuje wszystkie litery na małe lub wielkie.
replaceAll() =replaceAll(@currentField, ' ', '') Zastępuje wszystkie wystąpienia danego znaku innym ciągiem.
Operacje na Datach Date() =Date([$DataTerminu]) Konwertuje ciąg znaków na obiekt daty do dalszych porównań.
addDays() =addDays(@now, 14) Dodaje określoną liczbę dni do daty (kluczowe przy wyliczaniu SLA).
toLocaleDateString() =toLocaleDateString(@currentField) Formatuje datę zgodnie z regionalnymi ustawieniami użytkownika.
@now (różnica dat) =floor((Date([$Termin]) - @now) / 86400000) Oblicza liczbę pozostałych dni do upływu terminu audytowego DORA.
Funkcje Matematyczne floor() / ceiling() =floor([$Kwota] / 1000) Zaokrągla liczbę w dół lub w górę do liczby całkowitej.
round() =round([$WskaznikRyzyka], 2) Zaokrągla wartość do określonej liczby miejsc po przecinku.
min() / max() =min([$WartoscWyliczona], 100) Ogranicza maksymalną lub minimalną wartość (np. szerokość paska postępu do 100%).

5. Trzy Zakresy Formatowania (Column, View, Form)

Dostosowywanie komórek tabeli, całych widoków wierszowych oraz formularzy edycji

DORA Governance

Silnik SharePoint umożliwia formatowanie na trzech odrębnych poziomach interfejsu użytkownika:

1️⃣ Formatowanie Kolumny (Column Formatting)

Dotyczy pojedynczej komórki. Zapewnia wizualizację statusów, pill badge'e, miniatury dokumentów, generowanie linków mailto: oraz przycisków szybkiej akcji.

Ustawienia: Menu kolumny > Ustawienia kolumny > Formatuj tę kolumnę > Formatuj za pomocą formatu JSON.

2️⃣ Formatowanie Widoku (View Formatting)

Obejmuje całą listę lub bibliotekę. Pozwala nadać klasę całemu wierszowi (additionalRowClass), zastąpić tabelę kafelkami (rowFormatter), sformatować nagłówki grup (groupProps) oraz ukryć zaznaczanie wierszy (hideSelection: true).

Ustawienia: Menu widoku > Formatuj bieżący widok > Tryb zaawansowany.

3️⃣ Formatowanie Formularza Listy (Form Formatting: Header, Body Sections, Footer)

SharePoint umożliwia podział formularza dodawania i edycji elementu na intuicyjne, wielokolumnowe sekcje (zakładki) oraz dodanie niestandardowego nagłówka z klauzulami poufności (Art. 104 Prawa Bankowego):

    }

}

9. Dobre Praktyki, Wydajność 5000+ & FAQ

Zalecenia optymalizacyjne, obsługa wartości null oraz typowe pułapki składniowe

Standardy Bezpieczeństwa

⚡ Wydajność i Limit 5000 Elementów

  • JSON nie omija progu widoku 5000: Formatowanie JSON działa po stronie klienta na danych zwróconych przez widok. Kolumny użyte w filtrach widoku muszą być zindeksowane!
  • Unikaj głębokiego zagnieżdżania DOM: Drzewo o głębokości powyżej 6 poziomów children spowalnia renderowanie widoków z paginacją na 100+ wierszy.
  • Optymalizuj pętle forEach: Renderuj pętle tylko wtedy, gdy pole nie jest puste, zabezpieczając się warunkiem =if(length(@currentField) > 0, ...).

🛡️ Bezpieczeństwo i Obsługa Błędów

  • Zawsze używaj nazw systemowych (InternalName): Zmiana nazwy wyświetlanej w ustawieniach listy nie psuje kodu, jeśli używasz [$InternalName].
  • Ochrona przed wartościami null: Sprawdzaj istnienie wartości przed wywołaniem funkcji tekstowych lub dat: =if(@currentField != '', toLocaleDateString(@currentField), 'Brak').
  • Poprawne cudzysłowy w actionParams: Parametry dla Flow muszą być zagnieżdżonym stringiem JSON ze scałkowanymi cudzysłowami: "{\"id\": \"GUID\"}".
1. Dlaczego formatowanie JSON nie działa po wklejeniu kodu i SharePoint wyświetla błąd walidacji? ▼
Najczęstszą przyczyną są błędy składniowe JSON: brakujący lub nadmiarowy przecinek po ostatnim elemencie tablicy/obiektu, niezamknięty cudzysłów w formule =if(...) lub literówka w nazwie właściwości CSS (np. align-item zamiast align-items). Przed wklejeniem kodu do SharePointa zawsze zweryfikuj plik w VS Code z podpiętym $schema.
2. Jak odwołać się do pola z biblioteki nadrzędnej (Lookup) w wyrażeniu JSON? ▼
W przypadku kolumn typu Lookup należy użyć selektora .lookupValue (wartość tekstowa) lub .lookupId (identyfikator ID rekordu w liście źródłowej), np.: [$NazwaKolumnyLookup.lookupValue]. Jeśli komórka może być pusta, zastosuj zabezpieczenie =if([$NazwaKolumnyLookup.lookupValue] != '', [$NazwaKolumnyLookup.lookupValue], 'Nie przypisano').
3. Czy formatowanie JSON jest widoczne w aplikacji mobilnej SharePoint i Microsoft Lists? ▼
Tak! Formatowanie kolumn i podstawowe formatowanie widoków jest natywnie interpretowane przez aplikacje mobilne Microsoft Lists (iOS/Android). Jednakże interaktywne panele customCardProps z zachowaniem hover są automatycznie zamieniane na dotyk (tap) w interfejsach dotykowych.
4. Czy kod JSON formatujący widok może wstrzykiwać zewnętrzne skrypty JS lub wywoływać zewnętrzne API? ▼
Nie. Ze względów bezpieczeństwa (w tym wymogów DORA i standardów cyberbezpieczeństwa sektora bankowego) silnik formatowania deklaratywnego jest całkowicie odcięty od możliwości wykonywania dowolnego kodu JavaScript czy wywołań fetch() / XMLHttpRequest. Jeśli proces biznesowy wymaga integracji zewnętrznej, jedynym dozwolonym łącznikiem jest akcja customRowAction: executeFlow, która bezpiecznie przekazuje żądanie do certyfikowanego przepływu Power Automate w chmurze Microsoftu.
